# step-33：黄金集难度升级 + 排序质量指标

## 目标

step-32 的 30 条用例全部 100% 通过。但这个"100%"是个坏信号：
**题目太容易，评估测不出任何改进**。语料只有 10 个文件 31 个块，
`top_k=3` 就能覆盖近 10% 的语料，随便问什么都能命中目标文件。
在这种尺子下，加 rerank、加 query 改写、调阈值，分数都不会动。

本步做两件事：把题目变难，把指标换成能反映"排序质量"的。

## 实现要点

### 1. 用例从 30 条扩到 55 条，新增 5 个难度维度

| 分类 | 条数 | 考什么 | 举例 |
|---|---|---|---|
| 基础题 | 25 | 回归基线（原有用例） | "退货的运费谁承担？" |
| **同义改写** | 8 | embedding 泛化：不含知识库原词 | "东西到手了发现不合心意，多久之内能反悔？" |
| **易混淆** | 5 | 抓对文件：相邻政策数字不同 | "质量问题想换一个新的，超过一周了还能换吗？"（15 天，不是 7 天） |
| **多跳** | 3 | 跨文件综合 | "退货寄回去以后，钱多久能退到银行卡？"（returns + refund） |
| **多轮指代** | 4 | 上下文理解 | 前文"我想退货" → "多久之内可以？" |
| 转人工 | 3 | 两条触发路径 | 新增"我要人工客服，机器人说不明白" |
| 超范围 | 3 | 礼貌拒绝 | 新增"我最近心情不好，能陪我聊聊吗" |
| 知识库外 | 4 | 不许编造（幻觉主要出口） | "能直邮到美国吗？"、"可以分期付款吗？" |

**易混淆题的杀伤力**：退货 7 天 / 换货 15 天、退货邮费（买家出）/ 换货运费（商家出）、
保修 1 年 / 退货 7 天。检索抓错文件时，LLM 会拿着正确格式的政策答错数字——
这种错误比"答不上来"危险得多。

### 2. 多轮用例的 schema 扩展（`history` + `retrieval_query`）

```json
{"id": "ctx-1", "history": ["我想退货"], "question": "多久之内可以？",
 "retrieval_query": "退货多久之内可以申请", "expect_sources": ["returns.md"]}
```

- **`history`**：本轮之前的用户发言，按序重放后才会问 `question`。
  "那它能退吗"这类追问离开上下文毫无意义，必须把指代链完整交给 Agent。
- **`retrieval_query`**：检索层该用哪句话去查。

`retrieval_query` 为什么必须有——**加载时强制校验**：
多轮用例的 `question` 通常带指代词，直接拿它检索必然不命中。
如果不强制写 `retrieval_query`，检索层就只能静默跳过，
产出"看起来在校验其实什么都没测"的用例——这比失败的用例更危险。
所以 `history` 非空 + 声明了 `expect_sources` 却没写 `retrieval_query` 时，加载直接报错。

它同时也是 **query 改写的目标上限**：如果哪天真的做了改写，就应该能自动产出接近这句话的查询。

### 3. 新增排序质量指标（`top1_ok` / `MRR`）

recall 视角的"命中率"在语料小的时候很快饱和，对优化完全不敏感。
补两个看排序的指标：

- **首条命中率**：第一个命中是否就是期望文件
- **MRR**：第一个正确来源的倒数排名（1.0 = 首条就对）

这两个才是 rerank、query 改写真正能推动的数字。

### 4. `--sweep`：多档 top_k 对比

```bash
uv run python scripts/run_eval.py --sweep 1,2,3,5
```

一次输出对比表。它的价值在于区分两种失败：
**召回不回来**（top_k 加到 5 也不行）vs **召回回来但排不准**（top_k=1 差、top_k=3 好）。
后者才是 rerank 的空间。

### 关键：证明多轮用例不是白给分

做了一组对照实验——同一条问题，有 `history` 和没 `history`：

| 条件 | 模型看到的 | 回答 | 判定 |
|---|---|---|---|
| 无 history | "多久之内可以？" | "多久之内可以**退货/退款**？多久之内可以**发货/送达**？告诉我具体问题" | **✗ 失败** |
| 有 history | "我想退货" → "多久之内可以？" | "自签收之日起 7 天内…可以申请无理由退货" | ✓ 通过 |

说明多轮重放是真的生效，`history` 不是摆设。
另一条 `ctx-4` 的回答明确引用了前文"刚买的手机"，同样印证了上下文传递。

## 诚实的结论：尺子还不够利

**变难了，但还是 100%。** 本步真正的收获不是"分数好看"，而是搞清楚了瓶颈在哪：

1. **检索层对 top_k 敏感了**（91.1% → 100%），说明尺子开始有区分度。
   但这只反映"多跳题需要 top_k≥2"，不代表排序能力差。
2. **排序质量已经很满**：首条命中率恒 95.6%（43/45），只有 `para-2`、`para-5` 首条不对。
   也就是说 **rerank 的理论收益上限只有 4.4%（2 条）**，现在做 rerank 测不出什么。
3. **生成层 100%**：LLM 足够强，即使检索到相邻文件也能靠推理答对。
   语料里每份文档都短且自洽，没有"干扰文档"。

**根因是语料规模**：10 个文件 31 个块，`top_k=3` 覆盖近 10% 语料。
要真正让尺子有区分度，必须**扩语料**——引入几十份文档、多份相似政策
（比如三个不同品类的退货规则、多版本活动条款），让 top_k=3 只覆盖 1~2%。
那时首条命中率和 MRR 才会有真实的下降空间，rerank 才有可量化的收益。

这已列入下一步，本步不顺手做（扩语料会触发 KB 重建，属于独立的一步）。

## 遗留问题

- **语料规模是唯一的真瓶颈**（见上），扩语料优先级最高
- 答案要点匹配仍是字符串包含，`expect_any` 里的同义表达要人工穷举
  （如"1-3"/"1~3"/"1至3"三种写法），后续可上 LLM-as-judge
- 多轮只测 2 轮，3 轮以上的指代链（"那它呢"→"那这个呢"）未覆盖
- 生成层单次跑分有随机性，波动幅度未测量（需重复 3 次看方差）
- `--sweep` 只有检索层，无法回答"top_k 变化对最终答案质量的影响"
- 转人工的"可接受阈值"仍无依据，0 条误转不代表没问题
