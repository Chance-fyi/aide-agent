# step-34：扩充知识库语料 + 黄金集防腐审计

## 目标

step-33 的结论是：**尺子不够利，根因是语料规模**。10 个文件 31 个块，
`top_k=3` 就覆盖近 10% 语料，检索躺着都能命中，rerank 的理论收益上限只有 4.4%。

本步把语料从 10 文件扩到 **46 文件 199 块**，让 `top_k=3` 只覆盖 1.5%，
并把黄金集同步扩到 96 条。同时补一个防腐机制——
扩语料踩到一个隐蔽的坑，必须有工具兜住。

## 语料设计：不是"多写点"，而是造"互相冲突的相似政策"

单纯增加文档量对检索难度帮助有限。真正制造难度的是
**同一业务问题存在多份都相关、但规则不同的文档**——
检索必须抓对那一份，抓错了 LLM 会拿着正确格式的政策答错数字。

| 组 | 文件数 | 设计意图 |
|---|---|---|
| 退货细则 | 6 | 通用 `returns.md` + 3C/生鲜/服饰/图书/大件五套**数字全不同**的细则 |
| 保修细则 | 5 | 通用 + 3C/大家电/服饰/家具，保修期 1 年 / 3 年 / 2 年 / 30 天 |
| 促销活动 | 4 | 618 / 双 11 / 秒杀 / 拼团，定金与价保规则**互相冲突** |
| 优惠券 | 4 | 通用 + 新人券/品类券/店铺券，叠加规则各不同 |
| 物流 | 5 | 普通/大件/冷链/跨境/同城，时效 48h / 3-5 天 / 7-15 天 / 3 小时 |
| 支付 | 5 | 通用 + 分期/企业采购/风控拦截 |
| 会员 | 4 | 等级会员 + PLUS 付费会员 + 成长值 + 企业会员 |
| 发票/售后/账号 | 11 | 电子票/专票、安装/延保/以旧换新、实名/隐私/反诈 |
| 其他 | 2 | 价保细则、预售定金 |

刻意制造的混淆点举例：

- **退货 7 天 vs 换货 15 天 vs 大件 30 天 vs 3C 质量问题 15 天**
- **退货邮费买家出 vs 换货运费商家出 vs 大件上门取件费按体积收**
- **价保**：`faq.md` 写 7 天，`service-priceprotect.md` 写 15 天（PLUS 会员 30 天），
  `promo-618.md` / `promo-1111.md` 只在活动期内保价，`promo-seckill.md` 明确不保价
- **定金**：`promo-618.md` 说逾期不退，`service-presale.md` 说商家原因可退

结果：46 文件 / 199 子块 / 199 父块，语料 36 KB。

## 关键设计：`expect_sources_any`（OR 语义）

扩语料后出现一个真实缺陷：**原有用例的期望变成了错的**。

```
warranty-1「买的手机保修多久？」
  原期望: expect_sources = ["warranty.md"]        → 检索命中 warranty-3c.md → 判失败
  但 warranty-3c.md 比通用 warranty.md 更精确
```

这不是模型错了，是**期望表达力不够**。`expect_sources` 只有 AND 语义，
表达不了"通用政策或品类细则任一都可接受"。

所以补 `expect_sources_any`：

| 字段 | 语义 | 用于 |
|---|---|---|
| `expect_sources` | 全部必须命中（AND） | 多跳题：真的需要多个文件 |
| `expect_sources_any` | 至少命中一个（OR） | 通用政策与品类细则均可接受 |
| 两者同时写 | AND 全部满足 **且** OR 至少一个 | 多跳 + 来源有弹性 |

加载时校验：同一个文件不能既写进 AND 又写进 OR（读不懂的期望直接拦）。
MRR 也把"可接受来源"算作命中，否则 OR 用例的排序质量会被低估。

修正了 8 条因扩语料而过时的期望。

## 踩到的坑：扩语料会静默腐化「知识库外」用例

`unkb-2`「可以分期付款吗？」挂在「知识库外」分类下，期望"不支持/没有"。
我扩语料时加了 `payment-installment.md`，模型答得**完全正确且有据可依**，
却被过时的期望判错。

**这类腐化最危险的地方是它的表现**：不报错、不崩，
只是"模型答对了却被判失败"。如果不是逐条看答案，很容易误判成"模型变差了"。

### 防腐工具：`--audit`

```bash
uv run python scripts/run_eval.py --audit
```

拿「知识库外」用例的问题去检索，看最高分。分数高 = 语料里有像样的内容 = 该复核。

阈值 0.65 是按实测校准的：

| 问题 | top1 分数 | 真相 |
|---|---|---|
| 可以分期付款吗？ | **0.743** | 真腐化（已有专门文档） |
| 你们支持货到付款吗？ | 0.594 | 假阳性（只命中支付方式列表，没有答案） |
| 能直邮到美国吗？ | 0.530 | 真·知识库外 |
| 你们有线下实体店吗？ | 0.477 | 真·知识库外 |

阈值取在 0.594 与 0.743 之间。只提示不自动改——
是否真的腐化要人看语料才能定。测试里锁住了这个区间，防止随意改动。

## 遗留问题

- **5 条真·检索失败未修**：它们正是 rerank / query 改写的目标，留给下一步量化
- **LLM 随机性未量化**：`shipping-2`、`cat-5` 单跑通过、全量失败，
  说明单次跑分有噪声。需要重复 3 次看方差，或固定 `temperature=0`
- **上游 503 频率不低**（96 条中 6 条）：跑分时长被拉长到 25 分钟，
  影响迭代效率。可考虑加自动重试
- **审计阈值按当前语料校准**，语料大幅变动后需重校
- `--audit` 只覆盖「知识库外」分类，其他分类的期望腐化仍靠人工
- 答案要点匹配仍是字符串包含，同义表达靠人工穷举
- 语料全为手写虚构内容，与真实电商政策存在差异，仅用于技术验证
