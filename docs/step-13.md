# Step 13 — 输入防护：提示注入、违禁词、空白消息

## 目标

把用户输入从"直接信任"升级为"先安检再进 Agent"。
此前仅有的防线是 max_length=2000（422）与提示词拒答（依赖 LLM 自觉）。

## 实现要点

### 1. guardrails 模块（app/core/guardrails.py）

- **注入检测**：高置信度正则（中文"忽略既往指令"/英文经典句式/套取 system prompt/越狱扮演）。
  只收录"出现即恶意"的表达，避免误伤正常咨询
  （如"收银系统提示音怎么关"不能拦）
- **违禁词**：内置最小集（枪支/毒品/代开发票/刷单兼职/博彩），
  业务可用 `BLOCKED_WORDS` 环境变量追加，零代码扩展
- **话术原则**：友好拒答不说"检测到攻击"等对抗性措辞，
  给出路（回到正常咨询），也不给攻击者探测信号（200 而非 4xx）

### 2. API 层短路（chat.py）

拦截发生在进 graph **之前**：
- 省一次 LLM 调用（成本/延迟）
- 不往 Checkpointer 写污染状态（会话历史干净）
- 拦截事件记 warning 日志留痕（脱敏截断 80 字符）

`INPUT_GUARDRAIL=false` 可整体关闭（仅调试用）。

### 3. 请求校验加固

`ChatRequest.message` 增加 validator：strip 后为空即 422。
此前 "   " 能通过 min_length=1，白白消耗一次 LLM 调用。

## 已知局限（如实记录）

- 正则注入检测必然可被变形绕过（同义改写/拼音/拆字）——
  本模块定位是"第一道闸"，最终防线仍是系统提示词 + LLM 判断
- 违禁词是子串匹配，存在误报可能（如商品名恰好含词），
  目前靠"最小默认集 + 业务自查追加"控制，未做分词
