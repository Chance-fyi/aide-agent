# step-40：双端前端重做 —— 去掉 AI 味，收敛成"仪表盘"式技术界面

## 目标

双端界面的功能早就齐了，但视觉上是典型的"AI 生成产物"：渐变背景、
悬浮阴影卡片、药丸形控件、四色气泡、汉字圆角头像。本步只做视觉与信息结构
重做，**不动任何业务逻辑**（WebSocket、转接状态机、权限校验一行未改）。

## 先说清楚"AI 味"到底是什么

不是玄学，是可以逐条指出的具体做法。旧版 `index.css` 里能数出 7 条：

| # | 旧做法 | 为什么读起来"像 AI 做的" |
|---|---|---|
| 1 | `radial-gradient(1200px 400px at 50% -100px, #e0eaff, transparent)` 铺满背景 | 顶部一团蓝光是最典型的 AI 落地页母题 |
| 2 | 顶栏 `linear-gradient(135deg, #1e293b, #0F172A)` | 深色渐变条，视觉上"想显得高级" |
| 3 | 每个面板 `border-radius: 16px` + `box-shadow: 0 4px 16px` | 所有东西都浮着，没有平面层级 |
| 4 | 999px 圆角：tab、chip、input、button、badge 全药丸 | 药丸泛滥是最强的"模板感"来源 |
| 5 | 气泡四色：蓝底白字 / 灰底 / 绿底 / 白底蓝描边 | 颜色在替语义打工，色弱用户直接丢信息 |
| 6 | 头像用汉字圆角块（智/用/客/席/舒） | 零信息量，且中文字体缺失时会变成方框 |
| 7 | 空态 = 大图标圆底 + 药丸快捷问 | 模板化空态的固定配方 |

## 新方向：Instrument Minimal（仪表盘 / 技术工具）

三条原则，全部可验证：

### 1. 颜色只做信号，不做装饰

整屏只有 **2 个彩色**：一个强调色（`#0e7490` 青蓝，用于交互 + 智能客服）
和一个告警色（`#b45309` 琥珀，用于排队）。其余全部是中性墨色阶。

角色不再靠气泡底色区分，而是靠**文字标签**（客户 / 智能客服 / 人工坐席）
+ 左侧 2px 色条。颜色从"唯一手段"降级为"加速识别"——这同时修掉了
旧版一个无障碍问题：色弱用户分不出三种气泡。

用户自己的消息是整屏唯一的实心重色块（`--ink-950` 底 + 白字），
指向性最强，也顺手省掉了"我是谁"的困惑。

### 2. 科技感来自等宽数字和网格，不来自霓虹发光

技能库给的 `--design-system` 两轮都推荐了 **HUD / Sci-Fi FUI**（霓虹青、
发光描边、扫描动画）和 **Glassmorphism**（毛玻璃）——这两者恰恰就是要
去掉的东西，而且 HUD 的可访问性风险标的是 `high`。所以**没有采用**它的
设计系统输出，只取了 `--domain typography` / `ux` / `icons` 的定向结论。

实际做法：

- 时间戳、会话 ID、计数、快捷问题序号、状态徽章、字段标签 → 一律等宽
  `ui-monospace` + `font-variant-numeric: tabular-nums`，天然对齐成列
- 队列计数显示 `03` 而不是 `3`（仪表读数的习惯）
- 顶栏品牌后缀 `SUPPORT CONSOLE` 大写等宽、字号 10px、字距 0.12em
- 1px 发丝线分隔，小圆角（4px / 6px 两档），**零阴影**

刻意**没有引入任何外部字体**：旧 CSS 里 `font-family` 写了 `"Outfit"`
但从来没 `@import` 过（等于永远走回退），中文项目加载 Inter/Fira 只会
换来 FOUT 和一次额外网络请求。系统字体栈在中文下的表现反而更稳。

### 3. 结构上把"卡片"换成"chrome + 工作区"

- 顶栏压成一条 48px 深色铭牌（`#0b0f14`），视图切换用扁平文字 + 底部
  2px 强调线，不再是分段药丸
- 用户端：满幅单列对话流，限宽 760px 居中（长行难读是聊天界面最常见的
  可读性错误）
- 坐席端：左侧 300px 队列栏用 `--surface-2`（比详情区深一档），形成
  "侧栏 / 工作面"关系，而不是两个等权重的白卡片

### 4. 状态从"横幅"移到"标题区"

旧版"在线 / 人工会话中"占一整条 42px 横幅，且靠 `visibility: hidden`
占位（空白条）。新版直接写进标题下方的一行状态（点 + 文字），
转接时才出现一条带左色条的细提示。省下 42px 垂直空间，信息也没少。

## 验证：自动化而不是"看着还行"

截图我看不了（当前模型不支持图像输入），所以把视觉要求全部转成
**可执行的断言**，用 CDP 驱动真实 Chrome 跑：

### 检查项（`/tmp/uicheck.py`，7 个视口/状态组合）

| 检查 | 结果 |
|---|---|
| 横向溢出（`scrollWidth > clientWidth`） | 0 |
| 仍有阴影的元素 | **0** |
| 仍有渐变的元素 | **0** |
| 文本对比度（正文 ≥4.5，大字 ≥3） | 全部通过 |
| 点击目标（桌面 ≥32px） | 全部通过 |
| emoji 当图标 | 无 |
| 关键容器存在且有尺寸 | 通过 |

7 个组合全绿：登录页、用户端空态、用户端对话、坐席端、用户端手机 375、
坐席端手机 375、坐席端平板 820。

### 检查抓到的真问题（都已修）

| 问题 | 数字 | 修法 |
|---|---|---|
| `queue-time` 时间戳对比度不足 | **2.88:1** | 淡灰 `#8a97a3` → `#5a6875`（5.7:1）。10px 也算正文，不能"看着淡就淡" |
| `prompt-key` / `thread-id` / placeholder 同上 | 2.98:1 | 统一提到 `--ink-500` |
| 登录页"注册一个"点击目标过小 | 112×**22** | 加 `padding: 8px 10px` → ≥32 |
| 手机端按钮高度不足 | 34~40px | 窄屏下 `.btn` / 输入框 / `.send` 全部 `min-height: 44px` |
| 坐席端缺 `h1` | `h1: 0` | 加视觉隐藏的"坐席工作台"，详情标题改 `h2` |

顺带把 `--ink-400` 的语义收紧了：它从 `#8a97a3`（白底 2.98:1）改成
`#626d79`（5.3:1），并且**只允许用于非文本**（图标、状态点）。注释里
写明了这条纪律，避免下次又被拿去写小字。

### 无障碍补充

- 消息列表 `role="log" aria-live="polite"`：WS 推来的新消息会被读屏播报，
  且不抢焦点（聊天场景不能因为来消息就挪走光标）
- 队列计数：视觉显示 `03`，`aria-hidden` 掉裸数字，另给
  `sr-only` 的"待处理会话 3 个"（技能库明确要求别念孤零零的数字）
- 选中态用 `aria-current`（队列项、视图切换），不只靠颜色
- 恢复历史期间显示骨架 + `aria-busy`，不是转圈也不是闪一下欢迎页
- 手机端全部交互元素 ≥44px

## 端到端复核（真后端，不是 mock）

重做只改 JSX/CSS，但必须确认没把数据流改坏：

**用户端**（真 uvicorn + 真 LLM）：
```
注册 → 注入登录态 → 首屏 {empty:true, prompts:3, log:true, role:"log", composer:true}
点第一个快捷问题 → bubbles:2, roles:["你","智能客服"]
回复内容: "您好，退货可以按以下步骤操作（依据平台退货政策）…"
```

**坐席端**（真队列）：
```
造一条关键词转接工单 → 队列 items:3, count:"03", badge:"排队中"
点开 → 详情 head:"林小满", bubbles:4, roles:["客户","智能客服","客户","客户"],
        接入按钮在, 回复栏隐藏（排队中不该出现）, 无横向溢出
```

## 遗留问题

- **没有深色主题**。当前是单浅色主题。深色版需要独立验证对比度
  （不能从浅色值推断），属于下一步的事。
- **没有在真机上验证**。375px 是用 DevTools 的设备指标模拟的，
  iOS Safari 的 `100dvh` 与安全区行为仍需真机确认。
- **截图未人工复核**。所有结论来自 CDP 断言（对比度/溢出/尺寸/结构），
  "好不好看"这一层没有经过人眼，交付后建议实际打开看一眼。
- **坐席端队列在窄屏只给 40% 高度**，会话很长时会挤。真要做移动坐席端
  应该改成"列表页 → 详情页"两屏切换，而不是上下堆叠。
- **等宽字体在 Windows 上**会落到 Consolas，中文标点宽度与 mac 略异，
  长文本对齐可能有一两像素差异。
- **快捷问题清单是硬编码的 3 条**，仍写在前端。理想做法是后端按知识库
  覆盖率给出高频问题。
