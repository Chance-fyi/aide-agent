# Step 16 — 父子结构检索 + 多格式文件拆分

## 目标

1. 检索命中的是 400 字碎片，LLM 拿到的上下文不完整（答不全、易断章取义）
2. 语料只有 .md：真实客服场景还有 txt / docx / pdf

## 父子检索（small-to-big）

- **子块**（≤400字）：向量化与检索单元——短文本向量语义聚焦，"找得准"
- **父块**（≤1500字）：子块所属完整小节，喂给 LLM，"答得全"
- **超长小节**（>1500字）：子块自为父块（自我兜底），避免父块过长稀释注意力
- 多个子块命中同一小节时**按父块去重**，重复政策不重复占用 LLM 上下文
- search_kb 侧兼容旧数据：`parent_content` 缺失时退回 content

实现只在 `_chunks_from_section` 一处：md 的小节与 txt/docx/pdf 的
"段落聚合小节"统一走同一套父子切分逻辑。

## 多格式拆分

| 格式 | 结构识别 | 处理 |
|---|---|---|
| .md | #/## 标题 | MarkdownHeaderTextSplitter（原有链路） |
| .txt | 空行分段 | 段落聚合为小节（≤800字）→ 父子切分，h1=文件名 |
| .docx | 提取段落 | 同 txt 流程 |
| .pdf | 逐页 extract_text | 同 txt 流程（扫描件无文字层 → 空结果，预期） |
| 其他 | — | 跳过 + debug 日志（目录混入无关文件不炸入库） |

加载器注册表 `_LOADERS`：新格式加一行即扩展。

## schema 升级的联动（步骤15 的机制兑现）

- `parent_content` 字段加入 schema，`KB_SCHEMA_VERSION` 1→2
- **新 schema 无法灌进旧集合**（动态字段没开）→ 换新集合是唯一正道；
  蓝绿机制保证：staging 构建 → 冒烟 → 切别名，线上检索全程可用
- test_store 的 module fixture 检测旧 schema 自动触发重建升级——
  旧数据无法平滑加字段，重建即迁移
